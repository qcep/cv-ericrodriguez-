Fundamentos

Modelo Mental de Spark Streaming para BI

Antes de escribir código, es crítico entender cómo Spark ejecuta el streaming. El modelo determina la correctitud, no solo la velocidad.

Los 3 Pilares

Pilar 1
Incremental
No reprocesa todo, solo lo nuevo desde el checkpoint
Pilar 2
Unificado
Misma API para batch y streaming
Pilar 3
Checkpoints
Rastrean offsets, estado y commits

Triggers: Decisión de Negocio

Trigger Comportamiento Uso en Dashboards
ProcessingTime Ejecuta cada N segundos KPIs en tiempo real (2-5s típico)
Once Un batch y se detiene Refrescos determinísticos
AvailableNow Procesa backlog y pausa Free Edition (sin processingTime)
Continuous Sub-segundo, sin micro-batches Ultra-baja latencia (raro en BI)
Regla para el curso

En Databricks Free Edition, usar availableNow=True. Para simular continuidad, generar más archivos y re-ejecutar los sinks. El checkpointing previene duplicados.

¿Por qué importan los checkpoints?

Sin checkpoint

  • Restart relee chunk de eventos
  • Dashboard muestra 2× valor real
  • Eventos tardíos perdidos o duplicados
  • Confianza del negocio erosionada

Con checkpoint

  • Spark reanuda exactamente donde dejó
  • Sin gaps, sin repeticiones
  • Idempotencia en re-ejecuciones
  • Dashboards confiables

Configurar Volume y Carpetas

En Databricks Free, todos los paths deben vivir dentro de un Unity Catalog Volume. Configuramos la estructura base del proyecto.

Estructura de Carpetas

dash_lab1 base_path

_chk checkpoints

Código de Setup

# 0) Imports y Spark session
from pyspark.sql import SparkSession
from pyspark.sql.types import StructType, StructField, StringType, TimestampType, DoubleType
from pyspark.sql.functions import col, window
spark = SparkSession.builder.getOrCreate()

# Configuración
CATALOG = "demo_cat"
SCHEMA = "streams"
VOLUME = "landing"

# Crear volume si no existe
spark.sql(f"CREATE VOLUME IF NOT EXISTS {CATALOG}.{SCHEMA}.{VOLUME}")

# Paths base
base_path = f"dbfs:/Volumes/{CATALOG}/{SCHEMA}/{VOLUME}/dash_lab1"
inbox_path = f"{base_path}/inbox"
checkpoint_dp = f"{base_path}/_chk"
bad_path = f"{base_path}/_bad"
delta_kpi = f"{base_path}/delta_kpi"

# Validar y crear carpetas
_ = dbutils.fs.ls(f"dbfs:/Volumes/{CATALOG}/{SCHEMA}/{VOLUME}")
for p in [base_path, inbox_path, checkpoint_dp, bad_path, delta_kpi]:
  dbutils.fs.mkdirs(p)

Generador de Órdenes

Función que simula un stream de eventos JSON escribiendo archivos en inbox/:

import json, time, uuid, random
from datetime import datetime

channels = ["web", "mobile", "pos"]
customers = [f"CUST-{i:03d}" for i in range(1, 16)]

def generate_orders_wave(n_files=2, rows_per_file=60, pause_seconds=1):
  for i in range(n_files):
    path = f"{inbox_path}/batch_{int(time.time())}_{uuid.uuid4().hex}.json"
    lines = []
    for r in range(rows_per_file):
      evt = {
        "order_id": uuid.uuid4().hex,
        "event_time": datetime.utcnow().strftime("%Y-%m-%dT%H:%M:%S.%fZ"),
        "customer_id": random.choice(customers),
        "amount": round(random.uniform(5.0, 250.0), 2),
        "channel": random.choice(channels)
      }
      lines.append(json.dumps(evt))
    dbutils.fs.put(path, "\n".join(lines), overwrite=True)
    print("Wrote:", path)
    time.sleep(pause_seconds)

Activity 2

Schema y Streaming Read

Los dashboards necesitan tipos consistentes. Enforzar un schema explícito previene que KPIs colapsen por datos malformados.

Challenge 1: Definir Schema

orders_schema = StructType([
  StructField("order_id", StringType(), True),
  StructField("event_time", TimestampType(),True),
  StructField("customer_id", StringType(), True),
  StructField("amount", DoubleType(), True),
  StructField("channel", StringType(), True),
])

Challenge 2: Streaming Source

orders_df = (spark.readStream
  .schema(orders_schema)
  .option("maxFilesPerTrigger", 1)
  .option("badRecordsPath", bad_path)
  .json(inbox_path)
)
orders_df.printSchema()
Output esperado root |-- order_id: string (nullable = true) |-- event_time: timestamp (nullable = true) |-- customer_id: string (nullable = true) |-- amount: double (nullable = true) |-- channel: string (nullable = true)
¿Por qué badRecordsPath?

Para capturar líneas JSON malformadas sin romper el stream. Si una línea no es JSON válido, va a _bad/ en lugar de crashear el job.

Construcción del KPI: Orders Per Minute

Agregación con ventana tumbling de 1 minuto sobre event_time. El resultado es un DataFrame listo para dashboards.

Challenge 3: Tumbling Window

kpi_df = (orders_df
  .groupBy(window(col("event_time"), "1 minute"))
  .count()
  .withColumnRenamed("count", "orders_per_minute")
)
orders_df event_time
window(1 min) tumbling
count() orders_per_minute
Nota sobre outputMode

En este lab usamos outputMode("complete") para simplicidad. En labs posteriores usaremos watermarks + append para KPIs inmutables.

Activity 4

Sinks: Console y Delta

Dos sinks con checkpoints independientes. Console para preview, Delta para serving layer del dashboard.

Challenge 4: Console Sink

q_console = (kpi_df.writeStream
  .format("console")
  .outputMode("complete")
  .option("truncate", "false")
  .option("numRows", 50)
  .option("checkpointLocation", f"{checkpoint_dp}/console")
  .trigger(availableNow=True)
  .start()
)
q_console.awaitTermination()

Challenge 5: Delta Sink

q_delta = (kpi_df.writeStream
  .format("delta")
  .outputMode("complete")
  .option("checkpointLocation", f"{checkpoint_dp}/delta_kpi")
  .trigger(availableNow=True)
  .start(delta_kpi)
)
q_delta.awaitTermination()
Checkpoints independientes

Cada sink tiene su propio checkpoint folder. No compartir checkpoints entre sinks — causaría conflictos de offsets.

Query del KPI

kpi = spark.read.format("delta").load(delta_kpi)
kpi.orderBy(col("window.start").desc()).show(10, truncate=False)

Troubleshooting

Validación y Problemas Comunes

Checklist de éxito y soluciones a issues frecuentes en Databricks Free Edition.

Success Checklist

  • Streaming read desde Volume con schema explícito.
  • KPI computado como orders_per_minute.
  • KPI table escrita a Delta con checkpointing.
  • Re-ejecución con availableNow procesa nuevos archivos y mantiene resultados consistentes.
  • Sin errores de runtime a través de múltiples waves.

Common Issues & Solutions

Problema Causa Solución
Volume access error Volume no existe o path incorrecto Crear Volume en UI, ajustar CATALOG/SCHEMA/VOLUME
Nothing printed to Console Sin archivos en inbox antes de availableNow Ejecutar generate_orders_wave() primero
DELTA_MISSING_TRANSACTION_LOG Lectura antes de primera escritura Ejecutar Delta sink una vez antes de leer
Duplicates Checkpoint paths cambiados entre runs No modificar checkpoint paths

Principios Clave

1. Reliability beats raw speed

Los dashboards deben ser correctos y queryables, no solo rápidos.

2. availableNow + checkpointing

Combinación clave para updates idempotentes y repetibles en Databricks Free.

3. Schema explícito siempre

Previene que KPIs colapsen por tipos incorrectos o datos sucios.

4. Checkpoints son production scaffolding

En storage durable, estables entre restarts, uno por sink.
